# Скил: spec-kit-ears

## 1. Назначение и триггеры

Скил заменяет расплывчатые пользовательские истории (User Stories) на математически точные спецификации поведения системы по стандарту EARS.

**Триггеры запуска:**
- Проектирование нового эндпоинта или сервиса в монолите.
- Высокий риск коллизий бизнес-логики со смежными доменами.
- Подготовка контрактной спецификации до написания тестов и кода.

---

## 2. Предусловия (Inputs)

1. Бизнес-требование или задача из тикет-трекера.
2. Доменная спецификация в `docs/domains/<домен>.md`.

---

## 3. Пошаговая процедура (Execution Steps)

### Фаза 1: Классификация требований по 5 паттернам EARS
1. **Ubiquitous (Вездесущее):** `СИСТЕМА ДОЛЖНА <действие>` — глобальные инварианты (логирование, форматы).
2. **Event-driven (По событию):** `КОГДА <событие>, СИСТЕМА ДОЛЖНА <действие>` — триггеры входящих запросов.
3. **State-driven (По состоянию):** `ПОКА <состояние>, СИСТЕМА ДОЛЖНА <действие>` — условия валидации баланса/прав.
4. **Unwanted behavior (Нештатное):** `ЕСЛИ <сбой>, ТО СИСТЕМА ДОЛЖНА <действие>` — обработка сетевых ошибок, нехватки средств.
5. **Optional (Опциональное):** `ГДЕ <флаг>, СИСТЕМА ДОЛЖНА <действие>` — фиче-тогглы и альтернативные шлюзы.

### Фаза 2: Фиксация контрактов данных (DTO)
1. Для каждого требования определить точные типы входных и выходных данных.
2. Запретить неточные типы (`float` для денег, невалидированные строки для дат).
3. Определить обязательность ключа идемпотентности для мутирующих операций.

### Фаза 3: Генерация приёмочной спецификации
1. Сформировать Markdown-файл спецификации в `specs/<фича>-ears.md`.
2. Провести согласование с архитектурными инвариантами проекта.

---

## 4. Выходные артефакты (Outputs)

1. `specs/<фича>-ears.md` — формализованная спецификация требований.
2. Чек-лист соответствия для автоматических тестов.

---

## 5. Ворота готовности (Definition of Done)

- [ ] Все функциональные сценарии описаны с использованием ключевых слов EARS (КОГДА, ПОКА, ЕСЛИ, ГДЕ).
- [ ] Описаны все негативные сценарии (Unwanted Behavior).
- [ ] Финансовые поля типизированы как `Decimal(precision=2)`.
- [ ] Спецификация не содержит двусмысленных местоимений и расплывчатых глаголов.

---

## 6. Стоп-условия и откат

- **Стоп-условие 1:** Требование не укладывается ни в один из 5 шаблонов EARS. Переформулировать совместно с автором задачи.
- **Стоп-условие 2:** Обнаружено противоречие с системными инвариантами `docs/architecture/layers.md`. Приоритет отдается системным инвариантам.

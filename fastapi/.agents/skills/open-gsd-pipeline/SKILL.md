# Скил: open-gsd-pipeline

## 1. Назначение и триггеры

Скил предотвращает расползание границ задачи (Scope Creep) и деградацию внимания модели (Attention Decay) при разработке крупных фичей в монолите. Переносит управление состоянием из памяти диалога на диск в директорию `.planning/`.

**Триггеры запуска:**
- Задача требует изменения более 2 файлов или затрагивает несколько архитектурных слоев.
- Разработка новой доменной фичи (например, сервис Billing).
- Сессия превысила 5 шагов диалога, замечена потеря фокуса модели.

---

## 2. Предусловия (Inputs)

1. Утвержденная цель задачи и нефункциональные требования.
2. Чистое состояние репозитория Git.
3. Доступен скрипт валидации плана `tools/plan_checker.py`.

---

## 3. Пошаговая процедура (Execution Steps)

### Фаза 1: DISCUSS (Фиксация инвариантов)
1. Создать манифест `.planning/PROJECT.md`.
2. Описать цель, границы задачи (Out of Scope) и список нерушимых правил.

### Фаза 2: PLAN (Декомпозиция на волны)
1. Создать дорожную карту `.planning/ROADMAP.md`.
2. Разбить задачу на атомарные фазы:
   - Фаза 1: Контракты и DTO (`schemas/`).
   - Фаза 2: Бизнес-логика и протоколы (`services/`).
   - Фаза 3: Транспортный слой API (`api/`).
   - Фаза 4: Верификация и Techlead Gate.
3. Каждая фаза должна затрагивать не более 2–3 файлов.

### Фаза 3: EXECUTE (Изолированные волны)
1. Для каждой фазы создается запись в `.planning/STATE.md` с указанием активной фазы.
2. Фаза выполняется изолированным субагентом со свежим контекстом (0 токенов предыстории).
3. Субагент читает с диска ТОЛЬКО артефакты предыдущей фазы.
4. После завершения фазы сессия субагента принудительно закрывается.

### Фаза 4: VERIFY (Контроль дрейфа)
1. Выполнить проверку плана:
   ```bash
   python3 tools/plan_checker.py
   ```
2. При обнаружении отклонений — до 3 итераций автоисправления.
3. При статусе PASS — переход к следующей фазе.

---

## 4. Выходные артефакты (Outputs)

1. `.planning/PROJECT.md` — манифест архитектурных рамок.
2. `.planning/ROADMAP.md` — дорожная карта с отметками выполненных шагов.
3. `.planning/STATE.md` — актуальное состояние контура.
4. Реализованный код фичи по слоям.

---

## 5. Ворота готовности (Definition of Done)

- [ ] Все артефакты `.planning/` материализованы на диске.
- [ ] Все фазы в `ROADMAP.md` отмечены как выполненные (`[x]`).
- [ ] Скрипт `tools/plan_checker.py` возвращает код 0 (PASS).
- [ ] Архитектурный дрейф равен 0.

---

## 6. Стоп-условия и откат

- **Стоп-условие 1:** Агент в рамках Фазы 1 пытается править код слоев API или сервисов. Немедленный `git checkout .`, повтор фазы с жестким промптом.
- **Стоп-условие 2:** `tools/plan_checker.py` возвращает FAIL после 3 попыток исправления. Эскалация человеку.

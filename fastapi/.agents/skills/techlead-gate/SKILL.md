# Скил: techlead-gate

## 1. Назначение и триггеры

Скил выполняет роль строгого технического лидера, дающего окончательное разрешение на слияние функционала в основную ветку монолита.

**Триггеры запуска:**
- Завершение всех фаз реализации задачи.
- Формирование финального Pull Request.
- Подготовка пакета приёмки воркшопа.

---

## 2. Предусловия (Inputs)

1. Все слои новой фичи реализованы на диске.
2. Созданы модульные и интеграционные тесты.
3. Доступен мастер-скрипт `tools/verify_techlead_gate.py`.

---

## 3. Пошаговая процедура (Execution Steps)

### Фаза 1: Запуск мастер-шлюза
Выполнить команду комплексной приёмки:
```bash
python3 tools/verify_techlead_gate.py
```

### Фаза 2: Последовательное прохождение 4 барьеров
1. **Барьер 1:** Синхронизация Базы Знаний через `tools/verify_kb_sync.py`.
2. **Барьер 2:** Соблюдение границ архитектурных слоев через `tools/verify_architecture_layers.py`.
3. **Барьер 3:** Бюджет зоны поражения (Blast Radius <= 7 файлов) через `tools/verify_blast_radius.py`.
4. **Барьер 4:** Полный регрессионный тест-сьют pytest (unit + integration).

### Фаза 3: Вынесение вердикта
1. При падении любого из 4 барьеров процесс прерывается мгновенно (Short-circuit Evaluation).
2. При успешном прохождении всех 4 барьеров выводится: `[TECHLEAD GATE: ACCEPTED]`.

---

## 4. Выходные артефакты (Outputs)

1. Протокол приёмки в консоли.
2. Гарантия готовности репозитория к релизу.

---

## 5. Ворота готовности (Definition of Done)

- [ ] Все 4 барьера вернули статус PASS.
- [ ] Итоговый код возврата строго равен 0.
- [ ] В логах нет ни одного предупреждения о нарушении архитектуры.

---

## 6. Стоп-условия и откат

- **Стоп-условие 1:** Сбой любого из 4 барьеров блокирует сдачу. Попытка коммита отклоняется.

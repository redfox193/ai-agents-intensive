# Оркестрация: Кодер → CODE_GATE → Панель техлидов → Суммаризатор

Оркестрировать роли конвейера как детерминированный конечный автомат. Каждый участник стартует в отдельном изолированном процессе, получает минимально необходимый вход и оставляет проверяемый машинно-читаемый артефакт.

## Когда читать / когда не читать

- **Читать:** когда задаче разработки в монолите требуется полный цикл: написание кода Кодером, независимый прогон детерминированных гейтов, приёмка коллегией техлидов и автоматическое формирование структурированного брифа на доработку.
- **Не читать:** для тривиальных правок документации или опечаток в одном файле, не требующих прогона коллегии судей.

## Нерушимые правила

1. **Единственный владелец состояния:** только Оркестратор запускает роли, считает циклы и фиксирует итоговый статус.
2. **Код меняет только Кодер:** судьи и суммаризатор работают в режиме STRICT READ-ONLY.
3. **Никакой веры на слово:** статус подтверждается кодами возврата команд и цитатами `файл:строка`.
4. **Нейтральность окружения:** запрещены абсолютные пути конкретной машины (`/Users/...`, `/home/...`) и захардкоженные хеши персонального окружения. Все пути относительны к корню репозитория или используют раскрытие `~/`.
5. **Предел циклов:** не более 3–5 проходов (по умолчанию 3). При повторении того же блокера дважды — эскалация человеку (`ESCALATE`).

## Роли и модели (OpenCode Go / Configurable Matrix)

| Роль | Шляпа / Задача | Модель по умолчанию (OpenCode) | Режим доступа |
|---|---|---|---|
| **Coder** | Реализация фичи (Цикл 1) или исправление по брифу (Циклы 2..N) | `opencode-go/deepseek-v4.1-flash` | Чтение и запись кода |
| **CODE_GATE** | 5 ступеней: база знаний, граф AST, слои, Blast Radius, тесты | Детерминированный скрипт проекта | Read-only проверка |
| **Judge-1** | **Скептик:** риски, дыры в контрактах, граничные условия, утечки | `opencode-go/deepseek-v4.1-flash` | STRICT READ-ONLY |
| **Judge-2** | **Реалист:** соответствие спеке EARS, простота, тесты | `opencode-go/glm-5.3-flash` | STRICT READ-ONLY |
| **Judge-3** | **Визионер:** границы слоёв, чистая архитектура, технический долг | `opencode-go/qwen3.8-flash` | STRICT READ-ONLY |
| **Summarizer** | **panel-rework-summarizer:** сворачивание находок в бриф `RW-001`... | `opencode-go/glm-5.3-flash` | Read-only синтез JSON |

Модели судей настраиваются через переменные окружения `OPENCODE_MODEL_JUDGE1`, `OPENCODE_MODEL_JUDGE2`, `OPENCODE_MODEL_JUDGE3` либо единый фолбэк `OPENCODE_MODEL`.

## Машина состояний

```text
INIT → CODER (Цикл 1: feature) → CODE_GATE
       ├─ FAIL → gate-failure-brief.json → CODER (Цикл + 1)
       └─ PASS → ПАНЕЛЬ ТЕХЛИДОВ (Judge-1, Judge-2, Judge-3)
                 ├─ ACCEPT (3/3 или нет блокеров) → READY (Merge)
                 ├─ REJECT → panel-rework-summarizer → panel-rework-brief.json → CODER (Цикл + 1)
                 └─ CRITICAL / EXCEEDED → ESCALATE (человек)
```

## Алгоритм исполнения

1. **Preflight:**
   - Определить корень проекта (`git rev-parse --show-toplevel`).
   - Проверить наличие спеки (`specs/*.md`) и параметров задачи (`task_id`).
   - Инициализировать каталоги артефактов `.ai-team/` и `handoff/`.

2. **Шаг 1. Кодер:**
   - **Цикл 1:** реализация фичи по скилу [`.agents/skills/feature/SKILL.md`](../feature/SKILL.md) на основе спеки EARS.
   - **Циклы 2..N:** исправление замечаний строго по скилу [`.agents/skills/rework/SKILL.md`](../rework/SKILL.md) на основе `handoff/panel-rework-brief.json` (пункты `RW-001`...) или `handoff/gate-failure-brief.json`.
   - Результат: сохранённый handoff Кодера в `handoff/coder.json` и изменённые файлы в `git status`.

3. **Шаг 2. CODE_GATE:**
   - Выполнить детерминированные проверки проекта по скилу [`.agents/skills/techlead-gate/SKILL.md`](../techlead-gate/SKILL.md): актуализация базы знаний (`tools/verify_kb_sync.py`), границы архитектурных слоёв, лимит Blast Radius и тесты (`tools/verify_techlead_gate.py`).
   - Если база знаний рассинхронизирована с кодом (нарушен инвариант Filing Back) или упали проверки — записать `handoff/gate-failure-brief.json` и направить Кодеру на доработку без вызова коллегии судей.

4. **Шаг 3. Панель техлидов (3 судьи):**
   - Выполняется по скилу [`.agents/skills/teamlead-panel/SKILL.md`](../teamlead-panel/SKILL.md).
   - Каждый судья запускается в отдельном свежем процессе с закрытым stdin (`< /dev/null`).
   - Судья оценивает пакет (спека, diff, вывод тестов, код) в своей шляпе (Скептик / Реалист / Визионер).
   - Ответ каждого судьи сохраняется в `.ai-team/panel/judge-<N>.json` (вердикт `ACCEPT` / `REJECT` и список находок с указанием `file:line`, описанием и тяжестью `BLOCKER` / `IMPORTANT` / `NOTE`).

5. **Шаг 4. Ревьюер брифов и суммаризатор (Summarizer):**
   - Если все судьи вернули `ACCEPT` и блокирующих замечаний нет: вынести вердикт `READY` (код 0).
   - Если есть замечания: запустить `panel-rework-summarizer`, который объединяет находки по схеме [`.agents/skills/teamlead-panel/references/panel-rework-brief-schema.md`](../teamlead-panel/references/panel-rework-brief-schema.md), исключает дубли и формирует компактный `handoff/panel-rework-brief.json`.
   - Если лимит циклов не исчерпан: передать бриф Кодеру для следующего цикла ([`.agents/skills/rework/SKILL.md`](../rework/SKILL.md)).
   - Если лимит исчерпан: вынести вердикт `ESCALATE` (код 2) для решения человеком.

## Декларативный запуск через OpenCode

Конвейер разработки запускается **декларативно** — агент OpenCode получает целевое состояние (DoD) и ссылку на скил оркестрации, после чего автономно ведёт цикл:

```bash
# Декларативный запуск полного цикла автономной разработки фичи:
opencode run --auto "Разработай фичу аудита списаний по спеке specs/billing-audit-ears.md согласно скилу .agents/skills/orchestrate-coder-reviewer-summarizer/SKILL.md.
DoD: Кодер реализует логику, CODE_GATE подтверждает чистоту слоёв и тестов, Панель техлидов выносит 3/3 ACCEPT, конвейер возвращает VERDICT: READY." < /dev/null
```

Оркестратор автономно переходит по состояниям FSM, вызывая роли по соответствующим скилам:
* **Кодер (Цикл 1):** `.agents/skills/feature/SKILL.md`
* **CODE_GATE:** `.agents/skills/techlead-gate/SKILL.md` (4 барьера)
* **Панель техлидов:** `.agents/skills/teamlead-panel/SKILL.md` (Judge 1 Скептик, Judge 2 Реалист, Judge 3 Визионер)
* **Суммаризатор:** `.agents/skills/teamlead-panel/SKILL.md` (при REJECT формирует `handoff/panel-rework-brief.json`)
* **Кодер (Циклы 2..N):** `.agents/skills/rework/SKILL.md` (точечные фиксы `RW-001`...)

### Офлайн-валидация и тестовый харнес (Test Harness)

Для автоматизированных тестов в CI и проверки целостности артефактов без вызова LLM используется встроенный валидатор:

```bash
# Быстрая проверка артефактов и пакета (< 2 с)
python3 scripts/orchestrate_pipeline.py --check

# Прогон комплексного шлюза CODE_GATE
python3 tools/verify_techlead_gate.py
```

## Definition of Done (DoD)

- [ ] Все роли запускаются изолированными процессами без сохранения чужих сессий.
- [ ] Судейская панель использует 3 независимые модели коллегии (по умолчанию `opencode-go/deepseek-v4.1-flash`, `opencode-go/glm-5.3-flash`, `opencode-go/qwen3.8-flash` или через `OPENCODE_MODEL_*`).
- [ ] При отказе суммаризатор создаёт валидный JSON `handoff/panel-rework-brief.json`.
- [ ] В скриптах и скиле нет персональных путей (`/Users/...`) и жёстко зашитых хешей хоста.
- [ ] Все пути конечного автомата (READY, REWORK, GATE_FAILURE, ESCALATE) покрыты тестами.

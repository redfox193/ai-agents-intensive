# Скил: monolith-knowledge-graph

## 1. Назначение и триггеры

Скил регламентирует извлечение минимально необходимого семантического контекста из монолита объемом более 100 000 строк кода.
Вместо подачи всего репозитория в контекст модели, скил строит AST-граф зависимостей и изолирует целевой домен.

**Триггеры запуска:**
- Поступление любой задачи на модификацию или добавление функционала в монолит.
- Необходимость выяснить радиус влияния изменения (Blast Radius) перед написанием кода.
- Появление ошибок `ImportError` или подозрение на циклические зависимости.

---

## 2. Предусловия (Inputs)

1. Репозиторий проекта находится в чистом состоянии Git (`git status --porcelain` пуст).
2. База знаний содержит корневой мета-индекс `docs/INDEX.md` (размер ≤ 115 KiB).
3. В проекте установлен интерпретатор Python 3.12+ со стандартной библиотекой `ast`.
4. Доступна утилита `tools/build_dependency_graph.py`.

---

## 3. Пошаговая процедура (Execution Steps)

### Фаза 1: Адресация через мета-индекс (Paging)
1. Выполнить поиск целевого домена в `docs/INDEX.md`.
2. Загрузить в контекст ровно один листовой документ спецификации (`docs/domains/<домен>.md`).
3. Зафиксировать список BreakageSignals для данного домена.

### Фаза 2: Построение и валидация графа зависимостей
1. Запустить построение графа связей:
   ```bash
   python3 tools/build_dependency_graph.py
   ```
2. Проверить код возврата (обязан быть 0).
3. Прочитать артефакт `specs/dependency-graph.json`.
4. Убедиться, что массив `cycles` пуст. При наличии циклов — немедленная остановка.

### Фаза 3: Локализация контекста (Scoped Retrieval)
1. Найти в графе целевой модуль, подлежащий модификации (например, `app.services.billing`).
2. Извлечь из массива `edges` всех прямых соседей (входящие и исходящие ребра).
3. Загрузить в рабочую память агента ТОЛЬКО найденные 2–4 файла. Чтение остальных файлов монолита запрещено.

### Фаза 4: Декларативная сходимость базы знаний (Filing Back)
1. Любое изменение публичного интерфейса, схемы, переменной окружения или перемещение файлов обязывает агента актуализировать `docs/INDEX.md` и `docs/domains/<домен>.md`.
2. Запустить верификатор декларативной сходимости:
   ```bash
   python3 tools/verify_kb_sync.py
   ```
3. Код возврата обязан быть 0. Без зелёного отчёта верификатора слияние запрещено.

---

## 4. Выходные артефакты (Outputs)

1. `specs/dependency-graph.json` — машиночитаемый граф связей монолита.
2. `specs/dependency-graph.mermaid` — визуальная архитектурная схема.
3. Локализованный набор файлов для контекста агента (не более 4 файлов).

---

## 5. Ворота готовности (Definition of Done)

- [ ] Мета-индекс `docs/INDEX.md` прочитан, определен целевой домен.
- [ ] Листовая спецификация загружена в контекст.
- [ ] Скрипт `tools/build_dependency_graph.py` выполнен с кодом 0.
- [ ] Граф зависимостей проверен на ацикличность (число циклов = 0).
- [ ] Декларативная сходимость (Filing Back): `python3 tools/verify_kb_sync.py` возвращает 0.
- [ ] Объем загруженного контекста не превышает 5 000 токенов.

---

## 6. Стоп-условия и откат

- **Стоп-условие 1:** Скрипт `build_dependency_graph.py` обнаружил циклический импорт. Немедленный откат последнего коммита (`git checkout .`), отчет об ошибке техлиду.
- **Стоп-условие 2:** Попытка агента прочитать файлы вне списка Scoped Retrieval. Блокировка хода, принудительный возврат к графу.
